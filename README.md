# VoidSniffer

**Визуализация занятого места на диске в виде treemap — мгновенно, по индексу [Everything](https://www.voidtools.com/), без повторного сканирования файловой системы.**

VoidSniffer не обходит диск заново. Он читает уже готовый индекс Everything и рисует дерево каталогов: папки — контейнерами, файлы — плитками, размеры — площадью. Первый экран появляется за доли секунды даже на дисках с миллионами файлов, а вложенные уровни догружаются по мере необходимости.

---

## История возникновения

Идея выросла из простого раздражения: инструменты вроде SpaceSniffer и WinDirStat каждый раз заново обходят файловую систему. На больших дисках и особенно на сетевых папках это занимает минуты, а при каждом запуске приходится ждать снова — хотя все нужные метаданные уже лежат в индексе Everything.

Первая версия VoidSniffer строила дерево одним запросом «весь диск сразу» и подолгу висела в состоянии «Запрос к индексу Everything…». Выяснилось два важных факта:

1. Everything отдаёт **точный рекурсивный размер каждой папки** — сумму всех вложенных файлов. Значит, чтобы узнать размер папки, не нужно обходить её содержимое.
2. Один большой запрос — это долго и хрупко, а много маленьких запросов «дети этой папки» (`parent:"..."`) — быстро.

Так проект перешёл к **ленивой загрузке**: при сканировании запрашивается только первый уровень, а глубже — по мере захода в папки и фонового дораскрытия. Это и стало основной архитектурной идеей: *данные уже посчитаны — их нужно только показать*.

Дальше проект обрастал удобствами: навигация с историей, фильтры, тултипы с точными размерами и датами, подсветка при наведении, контекстное меню Windows, управление глубиной, тайл свободного места, тёмная тема SpaceSniffer-стиля, локализация и конфигурация.

## Ключевая идея

```mermaid
flowchart LR
  E[(Индекс Everything)] -->|IPC: parent:"путь"| P[EverythingDataProvider]
  P --> L[ProgressiveTreeLoader<br/>размеры уже готовы]
  L --> T[TreemapControl<br/>рекурсивная отрисовка]
  T --> U[Пользователь]
```

- **Без сканирования диска.** Ни одного `FindFirstFile`/рекурсивного обхода — только запросы к индексу.
- **Ленивость.** Стоимость открытия папки — один запрос, а не обход поддерева.
- **Точные размеры.** Папки берут размер-агрегат из индекса; файлы — собственный размер.
- **Прогрессивность.** Вложенность дорисовывается по мере поступления данных и настраиваемой глубины.

## Возможности

- Рекурсивный treemap с ограничением глубины и плавной подсветкой при наведении.
- Навигация: вход по двойному клику, назад/вперёд, вверх, к корню; адресная строка следует за текущей папкой.
- Фильтр по имени (подстрока) и диапазону размеров, с сохранением структуры дерева.
- Тултип: имя, логический размер, размер на диске, рекурсивные счётчики файлов/папок, даты, полный путь.
- Длительное нажатие ПКМ — системное контекстное меню Windows для файла/папки.
- Кнопки глубины `−`/`+` (1..8), тайл «Свободно», выбор папки кнопкой «Открыть…».
- Локализация через langpack-файлы (ru/en, легко добавить свой).
- Настройки в `VoidSniffer.ini` рядом с exe.
- CLI: `scan <путь>`, `--lang=<код>`.
- Опциональная поддержка нового pipe-API Everything 1.5 (SDK3) с откатом на классический IPC.

| Зависимости | Everything + .NET 4.8 | нет (portable) | нет | нет | нет (устарело) |

### Плюсы VoidSniffer

- **Скорость за счёт индекса.** Нет повторного обхода диска: открытие папки — один запрос к уже посчитанному индексу. Особенно заметно на повторных запусках и больших деревьях.
- **Сетевые пути без «пересканирования».** Если сетевые папки проиндексированы Everything, VoidSniffer показывает их так же быстро, как локальные; сам он по сети не ходит.
- **Минимализм.** Нет установки драйверов, служб и фоновых сканеров; один exe + Everything.
- **Не нужны права администратора** (в отличие от MFT-подхода WizTree).
- **Ленивая память.** В памяти только то, что реально просмотрено/дораскрыто, а не всё дерево целиком.
- **Точные агрегаты.** Размер папки — из индекса, а не приблизительная сумма, собранная по частям.
- **Расширяемость.** Langpack-файлы, ini-настройки, опциональный SDK3.

### Минусы и ограничения

- **Зависимость от Everything.** Нужен установленный и запущенный Everything; без него приложение не работает.
- **Качество данных = качество индекса.** Если в Everything выключены «Размеры папок/файлов» или даты, часть данных будет пустой — приложение предупредит об этом. Исключённые из индекса пути не видны.
- **Актуальность индекса.** Скорость достигается за счёт того, что данные уже собраны; изменения появляются с задержкой индексации.
- **Нет собственного сканера.** Если путь не индексируется Everything, VoidSniffer его не покажет (принципиальный отказ от обхода ФС).
- **Фильтр работает по загруженному дереву**, а не по всему индексу: чтобы «увидеть» глубже, нужно увеличить глубину/раскрыть папку.
- **Меньше возможностей анализа.** Нет статистики по расширениям, экспорта отчётов, поиска дубликатов и т.п.
- **Windows-only, .NET Framework 4.8.**
- **SDK3 (Everything 1.5 beta) нестабилен** — по умолчанию используется классический IPC; pipe-режим включается вручную.

## Требования

- Windows 7+ (проверялось на Windows 10/11), .NET Framework 4.8.
- [Everything](https://www.voidtools.com/) 1.4+ (рекомендуется 1.4; 1.5 работает, но его pipe-API пока в бете).
- В Everything включены: **«Размеры файлов»**, **«Размеры папок»**, желательно даты (создания/изменения/доступа). Инструмент предупредит, если чего-то не хватает.

## Сборка и тесты

```powershell
# сборка (Visual Studio 2022 / MSBuild)
msbuild VoidSniffer.sln /p:Configuration=Debug

# юнит-тесты
dotnet test VoidSniffer.Tests\VoidSniffer.Tests.csproj

# системные тесты (нужен запущенный Everything)
VoidSniffer.SystemTests\bin\Debug\VoidSniffer.SystemTests.exe "C:\"
```

Проект собирается классическим MSBuild; тесты — xUnit (`net48`). Системные тесты проверяют живую интеграцию: совпадение имён с диска, размеры, счётчики, даты, ленивую загрузку и инварианты раскладки.

## Запуск

```powershell
VoidSniffer.exe
VoidSniffer.exe scan "C:\Program Files"
VoidSniffer.exe scan C:\
VoidSniffer.exe --lang=en scan "C:\Users"
```

Путь можно передать просто аргументом, через `scan` или `--scan=...`; язык — `--lang=xx` / `--lang xx` / переменная `VOIDSNIFFER_LANG` / настройка в ini.

## Управление

- **Двойной клик** по папке — войти.
- **Короткий правый клик** — на уровень вверх; **длительное удержание ПКМ** — системное меню (Открыть, Свойства, …).
- **Alt+← / Alt+→ / Alt+↑** — назад / вперёд / вверх; **F5** — сканировать.
- **`−` / `+`** — глубина вложенности; **«Свободно»** — тайл свободного места; **«Открыть…»** — выбор корня.
- **Фильтр** — подстрока имени и диапазон размеров (МБ) в текущем загруженном дереве.

## Настройки (`VoidSniffer.ini` рядом с exe)

| Ключ | Назначение |
|---|---|
| `language` | Язык (`ru`, `en`, код из `lang\<код>.lang`); пусто — авто |
| `sdk3` | Использовать pipe-API Everything 1.5 (0/1) |
| `max_results` | Лимит записей на один запрос |
| `recursion_depth` | Глубина вложенности от текущей папки (1..8) |
| `show_free_space` | Тайл свободного места тома |
| `auto_expand`, `auto_expand_budget`, `auto_expand_seconds` | Фоновое дораскрытие |
| `window_width`, `window_height`, `window_maximized` | Размер/состояние окна |
| `last_path` | Последний просканированный корень |

Описания и значения по умолчанию — прямо в файле (они сохраняются при перезаписи).

## Локализация

Строки интерфейса — в `lang\ru.lang` и `lang\en.lang` (UTF-8, формат `ключ=значение`). Встроенные пакеты служат фолбэком; файл рядом с exe переопределяет их и может содержать лишь часть ключей.

Чтобы добавить язык: скопируйте `lang\en.lang` в `lang\de.lang`, укажите `language.code=de`, `language.name=Deutsch`, `language.plural=en` и переведите значения.

## Архитектура (кратко)

- `EverythingDataProvider` — IPC-обёртка: классический `WM_COPYDATA Query2` и опциональный SDK3-пайп; сериализация запросов, таймауты, фолбэк.
- `ProgressiveTreeLoader` — ленивая загрузка уровнями, размеры из индекса, идемпотентное раскрытие.
- `AutoExpansionPolicy` / фон — дораскрытие крупнейших папок до заданной глубины с бюджетом.
- `FilterService` — фильтрация загруженного дерева с сохранением структуры.
- `NavigationController` — фокус, back/forward, восстановление по пути.
- `TreemapControl` + `TreemapLayout` — squarified-раскладка, цвета, подписи, hover, тултипы, контекстное меню.
- `Localization`, `AppSettings`, `IndexDiagnostics` — i18n, конфиг, проверка параметров индекса.
